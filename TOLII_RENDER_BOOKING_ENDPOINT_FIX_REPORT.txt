1. VERIFIED ROOT CAUSE
--------------------------------------------------------------------------------
Issue on Physical Device:
The Booking Review screen showed the error:
"Booking service endpoint unavailable (HTTP 404). Deployed Render server needs backend update."

Investigation & Evidence:
1. Probing the live Render service (https://tolli-app.onrender.com):
   - GET / returns:
     {"status":"online","service":"TOLII OTP Authentication Service", ...}
   - POST /api/verify-otp returns HTTP 400 (Email and OTP required)
   - POST /api/bookings/prepare-payment returns HTTP 404 (Cannot POST /api/bookings/prepare-payment)
   - GET /api/coupons returns HTTP 404 (Cannot GET /api/coupons)
   - GET /api/bookings/availability returns HTTP 404 (Cannot GET /api/bookings/availability)

2. Root Cause Analysis:
   - The remote Render web service `tolli-app` is connected to the GitHub
     repository `toliiteam-sudo/Tolli-App` on branch `email-otp-auth`.
   - The last commit deployed on Render was `a3f3b9d` ("diagnostics: include
     configured clientId prefix in test-transports") from early October 2026,
     which strictly contained the OTP email authentication server.
   - The new booking endpoints (/api/bookings/prepare-payment, /api/payments/verify,
     /api/coupons, /api/bookings/availability, etc.) were created locally in the
     development environment in `server/index.js`, but had NOT yet been pushed
     to the remote GitHub repository branch `email-otp-auth` that Render tracks.
   - On the physical Pixel 9a, when ADB reverse was inactive, the Flutter app
     attempted 127.0.0.1:3000 (which looped to the phone itself and failed),
     localhost:3000 (failed), 10.0.2.2:3000 (failed), and then fell back to the
     remote Render URL `https://tolli-app.onrender.com`.
   - Because Render was running the older commit without booking routes, Render's
     Express router returned HTTP 404 (`Cannot POST /api/bookings/prepare-payment`),
     triggering the exact error banner displayed on the phone.

6. MANUAL STEPS TO UPDATE RENDER
--------------------------------------------------------------------------------
To update the deployed Render service so the phone can book without needing
a connected computer or ADB reverse:

STEP 1: Push the prepared commit to GitHub
Run the following command from the project root:
```bash
git push origin email-otp-auth
```
(If prompted for authentication, log in with your GitHub account `toliiteam-sudo`
or use a GitHub Personal Access Token).

STEP 2: Configure Environment Variables in Render Dashboard
1. Open the Render Dashboard: https://dashboard.render.com
2. Select the `tolli-app` Web Service.
3. Go to "Environment".
4. Ensure the following keys are added to Environment Variables:
   - `RAZORPAY_KEY_ID` = your Razorpay Test Key ID (starts with rzp_test_)
   - `RAZORPAY_KEY_SECRET` = your Razorpay Test Key Secret
   - `RAZORPAY_WEBHOOK_SECRET` = your chosen webhook secret string
   - `NODE_ENV` = production
5. Save changes.

STEP 3: Verify Render Deployment
- Render will automatically trigger a build upon receiving the push.
- Once deployed, GET https://tolli-app.onrender.com/ will show online.
- POST https://tolli-app.onrender.com/api/bookings/prepare-payment will return
  HTTP 200 for valid requests instead of HTTP 404.

STEP 4: Immediate Physical Device Testing (Right Now)
You do NOT have to wait for Render deployment to test right now:
The local backend is running on port 3000, and ADB reverse proxy is active.
Simply tap "Pay via Razorpay" on your connected Pixel 9a. The phone will
communicate with the local server, prepare the genuine Razorpay test order,
and display the Razorpay checkout sheet.
